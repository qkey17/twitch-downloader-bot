# TCD — обзор архитектуры

TCD — Telegram-бот для получения чата Twitch VOD, подготовки интерактивной HTML-страницы и выдачи пользователю результата.

## Поток обработки

1. Telegram handlers принимают ссылки, ID VOD и команды, проверяют доступ и управляют задачами.
2. Twitch API-модули получают сведения о VOD и страницы сообщений чата. Дополнительные метаданные используются при формировании HTML.
3. Worker обрабатывает сообщения и передаёт их HTML renderer; крупная обработка использует временное дисковое хранилище.
4. Publisher публикует готовую HTML-страницу и сохраняет сведения о результате в SQLite.
5. Пользователь получает ссылку или доступный результат через Telegram. История и повторное открытие используют реестр готовых страниц.

## Основные компоненты

| Компонент | Расположение | Назначение |
| --- | --- | --- |
| Запуск и конфигурация | `src/main.py`, `src/config.py` | Инициализация, настройки, Telegram long polling и завершение процесса |
| Telegram UI и обработчики | `src/handlers/`, `src/ui/` | Команды, сообщения, callbacks и пользовательские карточки |
| Twitch | `src/twitch_api/` | Клиент, метаданные VOD, чат и вспомогательные данные |
| Обработка задач | `src/workers/` | Получение, прогресс, отмена и подготовка результатов |
| HTML | `src/html_renderer.py`, `src/html_publisher.py`, `src/viewer_template.html`, `src/ready_html.py` | Рендеринг, шаблон, публикация и открытие готовых страниц |
| SQLite | `src/database/` | Кеш, реестр готовых HTML, история и связанные данные |
| Очистка | `src/html_cleanup.py` | Обслуживание файлов с защитой текущих зарегистрированных результатов |

## Хранение и runtime

SQLite хранит кеш и реестр текущего HTML-результата; личная история включается настройкой. При повторной успешной обработке публичная HTML-страница сохраняет постоянное случайное имя, а содержимое файла заменяется атомарно. Актуальные страницы не удаляются автоматической очисткой. Одноразовая очистка накопленных старых HTML завершена.

Production работает на Oracle Cloud Always Free. Выпуски выполняются вручную запускаемым GitHub Actions с действующими maintenance и recovery-процедурами. Этот обзор служит картой кода; подробности конфигурации, публикации, backup и выпуска находятся в [README](README.md) и [профильных документах](docs/oracle-deployment.md).

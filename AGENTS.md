# Инструкции Codex для TCD

## Источники

- Сначала прочитайте этот файл и [обзор архитектуры](PROJECT_OVERVIEW.md).
- Для поведения опирайтесь на актуальный код и соответствующие тесты.
- Используйте профильные документы по теме и [docs/roadmap.md](docs/roadmap.md) для открытых планов.
- Корневые [AUDIT.md](AUDIT.md) и [ROADMAP.md](ROADMAP.md) — архивные исторические записи, не текущие списки дефектов или задач.

## Безопасная разработка

- Делайте минимальные адресные изменения; не переписывайте соседний код без необходимости.
- Сохраняйте Telegram-сообщения, кнопки, callbacks и сценарии; сохраняйте внешний вид и поведение HTML-просмотрщика.
- Не теряйте данные SQLite, историю, реестр результатов и существующие HTML. Не меняйте схему или семантику данных без явного разрешения владельца.
- Храните секреты в окружении или настроенном менеджере секретов. Не выводите значения секретов и личные данные.
- Сохраняйте намеренное сообщение про «казуала» после получения ссылки на VOD.
- Не выбирайте инфраструктуру, провайдера, новый способ публикации или глобальные лимиты загрузок самостоятельно.

## Проверки и PR

- Подбирайте проверки по риску: для небольшой правки достаточно адресных тестов и проверок документации; не требуйте полный suite и аудит для каждой мелочи.
- Запускайте тесты только если они уместны или требуются задачей. Сообщайте только фактически полученные результаты.
- Для изменений создавайте один PR в `main`; проверяйте точный HEAD, review и обязательный CI перед merge. Используйте squash merge, когда он разрешён сценарием задачи.
- Не изменяйте опубликованную Git-историю, не force-push, не делайте reset и не удаляйте ветки без явного разрешения владельца.
- Не выполняйте merge, deployment, изменения production-данных или опасные операции без явного согласования в задаче.

## Production

Приложение разворачивается только через вручную запускаемый GitHub Actions workflow и действующие maintenance A*, deployment guard и recovery runbook. Прямой SSH-deployment приложения запрещён. Начинайте с preflight непосредственно перед рискованными действиями; следуйте установленным барьерам, не обходите guard. Используйте [Oracle deployment](docs/oracle-deployment.md), [backup/restore](docs/backup-restore.md), [daily backup](docs/daily-backup.md) и [offsite backup](docs/offsite-backup.md), не копируя их процедуры сюда.

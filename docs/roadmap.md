## Следующий функциональный приоритет Main

**Отправка уже готового HTML-чата непосредственно в Telegram без повторной
генерации.** PR #31 объединён в main: внутренний Cloud sender до 40 MiB реализован
и проверен автоматическими тестами, но ещё не развёрнут. Telegram UI находится
в разработке в отдельном PR; ручная отправка через настоящий Telegram ещё не
проверена. PR #27 открыт и не является зависимостью этого этапа.

- Отправлять существующий ready HTML, не создавать новую generation ради отправки.
- Безопасно проверять путь и доступность файла; не читать огромный HTML целиком
  в RAM и учитывать предел размера выбранного Telegram API.
- Исключить повторные конкурентные отправки; согласовать взаимодействие с cleanup,
  публикацией и lifecycle worker, включая maintenance/graceful shutdown.
- Сохранить существующие ссылки и доступ к результату; предусмотреть понятное
  поведение при слишком большом файле и ошибке отправки, без лишних кнопок/экранов.

Потоковая передача через текущий Cloud-стек подтверждена локально; это не измерение
RAM Oracle. Для файлов больше 40 MiB отдельно оценить Local API, ресурсы Oracle
и backup. Production-развёртывание и ручная приёмка отправки требуют отдельного этапа.

## Local Bot API — отдельное решение

- PR #26 завершён: закреплённая официальная сборка, artifact, образец unit и
  [инструкция](local-bot-api.md). Сервер Local Bot API на Oracle не устанавливался,
  Telegram endpoint не переключался.
- PR #27 открыт: opt-in Cloud/Local конфигурация требует отдельного review и решения.
  Он не входит в production; даже его merge не разрешает включать Local API.
- Установка, права/credentials, RAM/CPU/disk, безопасность и переход Cloud→Local
  с планом возврата требуют отдельных согласований и ресурсных проверок.
- Для больших HTML учитывать offsite budget 1,5 млрд байт и reserve 10 GiB:
  почти 2 GiB файл не обязан уложиться в бюджет после сжатия. Лимиты не меняем.

Инструкция описывает будущий Local-путь доставки HTML после стабилизации Local API.
Его обязательность для любой отправки небольшого файла через Cloud не установлена.
В PR #27 также меняется этот roadmap: при интеграции нужно согласовать разделы
приоритетов и Local API, сохранив актуальные статусы релиза и ручной приёмки.

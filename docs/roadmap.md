## Следующий функциональный приоритет Main

**LIVE-маркировка VOD и неполного HTML-чата.** PR #34 объединён и развёрнут
вместе с PR #35. Следующие четыре согласованные правки подготовлены к review:
Текущий stream ID из Helix сопоставляется с `stream_id` конкретного archive VOD.
Ошибка/неизвестный статус не доказывают LIVE. В списке один кешируемый lookup на
канал (TTL 30 секунд), при генерации — свежая проверка. Отсутствие превью не
используется как признак LIVE и не заменяется фиктивной картинкой.

Факт `captured_during_live` сохраняется в существующем `meta_json` generation и
встраивается в HTML; предупреждение готового результата/истории не зависит от
дальнейшего статуса Twitch. Старые поколения без флага остаются совместимыми.
Схема, файлы `src/database`, зависимости и deployment guard не меняются.

**Готовый HTML через Telegram:** PR #31 (Cloud sender до 40 MiB), #32 (UI) и #33
(узкий deployment guard) уже объединены и развёрнуты. Ниже сохраняются требования
этого завершённого этапа; полный ручной сценарий доставки ещё требует подтверждения.
PR #27 открыт и не является зависимостью.

- Отправлять существующий ready HTML, не создавать новую generation ради отправки.
- Безопасно проверять путь и доступность файла; не читать огромный HTML целиком
  в RAM и учитывать предел размера выбранного Telegram API.
- Исключить повторные конкурентные отправки; согласовать взаимодействие с cleanup,
  публикацией и lifecycle worker, включая maintenance/graceful shutdown.
- Сохранить существующие ссылки и доступ к результату; предусмотреть понятное
  поведение при слишком большом файле и ошибке отправки, без лишних кнопок/экранов.

Потоковая передача через текущий Cloud-стек подтверждена локально; это не измерение
RAM Oracle. Для файлов больше 40 MiB отдельно оценить Local API, ресурсы Oracle
и backup. Deployment выполнен; полная ручная приёмка отправки остаётся отдельной.

## Local Bot API — отдельное решение

- PR #26 завершён: закреплённая официальная сборка, artifact, образец unit и
  [инструкция](local-bot-api.md). Сервер Local Bot API на Oracle не устанавливался,
  Telegram endpoint не переключался.
- PR #27 открыт: opt-in Cloud/Local конфигурация требует отдельного review и решения.
  Он не входит в production; даже его merge не разрешает включать Local API.
- Установка, права/credentials, RAM/CPU/disk, безопасность и переход Cloud→Local
  с планом возврата требуют отдельных согласований и ресурсных проверок.
- Для больших HTML учитывать offsite budget 1,5 млрд байт и reserve 10 GiB:
  почти 2 GiB файл не обязан уложиться в бюджет после сжатия. Лимиты не меняем.

Инструкция описывает будущий Local-путь доставки HTML после стабилизации Local API.
Его обязательность для любой отправки небольшого файла через Cloud не установлена.
В PR #27 также меняется этот roadmap: при интеграции нужно согласовать разделы
приоритетов и Local API, сохранив актуальные статусы релиза и ручной приёмки.

## Последующая переработка Telegram UI

«Обработать чат заново», «🌐 Посмотреть чат онлайн», «📥 Скачать чат файлом»;
доступные действия готового результата идут отдельными строками online → файл → VOD.
Telegram filename строится из сохранённых channel/created_at generation, без
переименования серверного HTML. Основной функционал принят владельцем с замечаниями ниже.

косметическое удаление/повторная отправка усложняет message binding и гонки.

Сократить переходы к готовым VODs: непосредственно открывать чат из карточки и
отдельно получать HTML-файл. Упростить избыточный текст, унифицировать карточки
списка и прямых ссылок, сохранив корректные историю и callback-навигацию.
Текущая небольшая доработка: ASCII-разделитель ` - ` в Telegram filename,
удаление избыточного заголовка готового чата, единое короткое LIVE-предупреждение
и существующее модальное окно VOD без thumbnail для LIVE (мышь/касание/клавиатура).
Изменения подготовлены к review; merge/deployment не выполнены. Старые HTML не
перезаписываются; серверные имена, registry, потоковая отправка и lease сохранены.

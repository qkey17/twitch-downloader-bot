# LIVE и историческая неполнота чата

Helix [Get Videos](https://dev.twitch.tv/docs/api/reference/#get-videos) возвращает
`stream_id` archive VOD. Он сравнивается с `id` из
[Get Streams](https://dev.twitch.tv/docs/api/reference/#get-streams) того же `user_id`.
Online-статус канала, дата VOD и отсутствие thumbnail сами по себе ничего не доказывают.
Неполные/ошибочные ответы дают unknown, загрузка чата остаётся доступной.

Список использует ограниченный кеш 64 channel/session entries с TTL 30 секунд,
включая offline/unknown. Одна проверка канала обслуживает все VOD страницы;
навигация не делает запрос на каждый элемент. Пассивная карточка Telegram не
обновляется в фоне; актуальность восстанавливается при следующем действии.
Метаданные непосредственно перед скачиванием используют свежий stream lookup.
Это best effort API observation, не атомарное наблюдение Twitch: задержки API и
ошибка во время проверки могут оставить LIVE неизвестным.

Worker сохраняет `captured_during_live` (true только при доказанном соответствии)
и `chat_capture_finished_at` в существующем `Publication.meta` → `meta_json`.
HTML получает тот же строгий boolean. Warning — статический текст с textContent,
Twitch-строки продолжают экранироваться существующим JSON serializer.
История указывает на cache slot и показывает метаданные выбранного текущего ready
результата, как и его ссылку. Новая генерация может иметь другой флаг; старый HTML
сохраняет встроенное предупреждение. Конец стрима сам по себе его не снимает.

`meta_json` уже принимает дополнительные поля: миграции и изменения защищённых
файлов БД не требуются. Старые/legacy результаты без признака не объявляются ни
LIVE, ни гарантированно полными. Cloud sender, lease-протокол, pagination/repair,
callbacks и действия существующих кнопок не меняются.

# Готовый чат: названия и имя документа

Кнопки используют общие UI labels. Доступные действия результата расположены
отдельными строками: online, файл, VOD; навигация остаётся после них. Недоступный
online или файл не подменяются фиктивным действием, callback data не меняются.

`ReadyHtml` после прежней проверки и pin generation вычисляет отдельное
`document_filename` по `meta_json.channel` и timezone-aware `meta_json.created_at`.
Дата переводится в UTC. Имя нормализуется NFC, опасные символы/управляющие коды
заменяются пробелом, channel ограничен 150 UTF-8 байтами. При неполных/невалидных
метаданных остаётся прежнее безопасное имя `chat_<vod>_<generation>.html`.
Меняется только `InputFile.filename`; файловая система, registry, ссылки и SHA
сохраняются. `read_file_handle=False`, lease и ограничения sender прежние.

## Почему Telegram может показывать «изменено»

При повторном открытии `handlers_vod._edit_progress_message_with_card` сначала
вызывает `render_card` для существующего message_id: текстовая карточка получает
`edit_message_text`. После optional preview тот же ID получает `edit_message_media`.
История аналогично сначала показывает текст, затем добавляет превью. Для standalone
результата `send_card` отправляет текст и может затем добавить фотографию edit.
Это реальные API edits; окончательное отображение отметки зависит от Telegram.

Устранение требует отправки новой карточки, удаления/retire старой и переноса
message-bound capabilities. Ожидание thumbnail перед первым отображением задержит
ссылки и всё равно не устранит edit уже существующего source message. Поэтому
в этом PR lifecycle оставлен прежним. Исчезновение отметки на реальном Telegram
не заявляется; дополнительных сообщений и изменений конкурентной логики нет.
